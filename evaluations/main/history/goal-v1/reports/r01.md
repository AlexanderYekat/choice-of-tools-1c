## Назначение и возможная роль

Публичный плагин для Codex и Claude Code плюс один stdio MCP-сервер `unica`
(Rust, workspace 0.12.0). Заявленная аудитория — ежедневная разработка
1С:Предприятия: метаданные, формы, роли, СКД, внешние обработки, запуск 1С и
поиск BSL. Вход — файловая выгрузка платформенного XML и рабочее пространство
с `v8project.yaml`; выход — типизированные `data` по 11 публичным tools.

Относительно цели это не «ещё один MCP со списком хелперов», а кандидат на
**платформенную основу контура** (C5, C6, C7, C10, C12): узкая внешняя
поверхность, внутренние движки спрятаны, skills подключают инструкции лениво.
Одновременно это конкурент r02/r15 по исследованию (C1–C2) и r10/r18 по
справке (C4). Роль «использовать целиком как единственный контур» ограничена
обычными формами (C3) и официальными хостами.

## Заявления и подтверждения

- **c01-facade** SOURCE. Публичная поверхность ровно 11 tools:
  `unica.view`, `apply`, `resolve`, `search`, `check`, `diff`, `run`,
  `docs`, `task.get`, `task.result`, `task.cancel`. Список зашит в
  `EXPECTED_COMPATIBILITY_TOOLS` и сверяется с `tools/list`
  ([s01-verification](../EVIDENCE.json)). Внутренние анализаторы и
  runner спрятаны за оркестратором ([s01-plugin-readme](../EVIDENCE.json)).
- **c01-progressive-skills** SOURCE. Skills лежат отдельно
  (`plugins/unica/skills/…/SKILL.md`) и маршрутизируют агента на те же
  `unica.*`; это progressive disclosure инструкций, не отдельных MCP tools.
- **c01-search-read** SOURCE. `unica.search` ищет по корпусам `text`/`names`
  с `limit`/`scope`; `unica.view` читает логический узел с `filter`/`limit`/
  `cursor`; `unica.resolve` — аварийный мост к физическому пути
  ([s01-tool-surface](../EVIDENCE.json)).
- **c01-search-limits** SOURCE. В ведомости поверхности: regex и symbol
  «остаются неподдержанными»; skill `module-placement` прямо пишет, что
  call graph «is not on the v0.13 surface». Это ослабляет C2 относительно
  заявлений README про «поиск BSL-кода».
- **c01-forms-managed** SOURCE. `form-edit` описывает «существующей
  управляемой формы»; словарь элементов — InputField/UsualGroup/Table
  управляемого приложения. `interface-edit` правит `CommandInterface.xml`
  подсистемы, не обычную форму.
- **c01-formtype-ordinary-known** SOURCE. Валидатор `help.add` принимает
  `Form.FormType` равный `Managed` или `Ordinary`
  (`help.rs`). Это знание свойства метаданных, не редактор обычной формы.
- **c01-runtime** DOCUMENTATION + частичный SOURCE. `unica.run` без `op`
  отдаёт словарь; в ведомости перечислены
  `infobase.create`, `source.import/export`, `artifact.build`,
  `cf.export/import`, `infobase.export/import`, `client.run` через
  внутренний v8-runner. Исполнение не проверялось.
- **c01-docs** SOURCE. `unica.docs` ищет по `platform-help` и
  `development-standard`; полный текст страницы канонический провод не
  отдаёт; `configuration-documentation` отвечает `unsupported_source`.
  Cargo.toml упоминает разбор `.hbk` через zip.
- **c01-host** DOCUMENTATION. Официальная установка — marketplace Codex/
  Claude. Пригодность как обычный MCP в Cursor не опровергнута (бинарь
  `unica` + `.mcp.json` stdio существуют), но не доказана.
- **c01-tests** SOURCE. В README плагина есть `cargo test` и Python
  unittest CI; каталог `crates/unica-coder/tests` и `tests/` есть.
  Запуск: NOT_RUN.

## Реализация, зависимости и проверки

Значимый путь обзора: агент видит 11 tools → `unica.view {}` допускает
workspace → `search` сужает кандидатов → `view` читает узел → `apply`
(dryRun/ifRev) меняет XML → `check` валидирует → `run` собирает/запускает.
Внутренние адаптеры skills запрещают звать напрямую.

Зависимости: Rust-ядро, ленивая доставка движков из `unica-toolchain`
(SHA-256), Git for Windows на native Windows, платформа 1С только для
runtime-операций, `bsl-parser`/`bsl-syntax` с git-rev `itrous/bsl-analyzer`.
Лицензия LGPL-3.0-or-later накладывает условия на производные, если ядро
линкуется в закрытый продукт.

Точки подключения: stdio MCP; skills — адаптер хоста, не ядро (C12
частично соблюдён: одно ядро, два манифеста `.codex-plugin` /
`.claude-plugin`). Отдельного публичного library API кроме бинаря не
смотрели.

## Оценка относительно цели

- Полезность: закрывает или сильно продвигает C5 (типизированный edit),
  C6 (`check`), C7 (`run`), C9–C11 (bounded JSON, индексы/движки вне
  контекста), C10 (11 tools + lazy skills), C4 (точечная справка).
  C1 частично: search/view есть, но symbol/call graph на v0.13 не
  заявлены как реализованные. C3 не закрыт: обычные формы не равны
  управляемым. C8 (целевой UI/тест) в просмотренном объёме не найден —
  `client.run` запускает клиент, не сценарий проверки.
- Готовность: продукт с тестами, миграциями и жёстким контрактом
  поверхности. Для ежедневного контура в Cursor — условно: нужен
  адаптер подключения, не обязательно свой движок.
- Доказанность: поверхность, skills и ограничение form-edit подтверждены
  исходниками. Поведение search/run/docs на реальной конфигурации —
  только документация поверхности, без RUN.

Альтернативы той же широкой роли нет среди 19 входов: ближайшие куски
закрывают отдельные capability (r02 explore, r12 edit XML, r09 build/test).
Контрпример, который меняет рекомендацию «ядро edit/run»: если на рабочих
базах преобладают обычные формы и Unica не читает/не пишет их структуру —
роль сужается до управляемого приложения и метаданных.

Предварительное решение: **использовать как основной edit/check/run/docs
facade и как образец минимальной поверхности**; не считать единственным
explore-движком и не считать доказанной поддержку обычных форм.

## Резюме для пользователя

Полезен для: узкий стабильный MCP (11 операций), изменение метаданных и
управляемых форм, статическая проверка узла, сборка/запуск 1С, точечная
справка, скрытие внутренних движков. Что не решает: полноценные обычные
формы; доказанный callers/callees; целевые UI-тесты; официальный хост
Cursor. Проверено: README, контракт tools, skills форм/справки, валидатор
FormType, Cargo workspace. Предварительное решение: взять как ядро
edit/verify-static/run и как эталон facade; explore и ordinary forms
закрывать другими компонентами. Следующая проверка: deep-static
`application/v13` + эксперимент `unica.view` на форме с
`FormType=Ordinary`.

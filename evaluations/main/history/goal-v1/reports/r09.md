## Назначение и возможная роль

Kotlin/Spring MCP «METR»: сборка ИБ (Designer или IBCMD), конвертация EDT,
запуск YaXUnit, синтаксис CheckConfig/CheckModules/EDT validate, запуск
конфигуратора и клиентов. Роль: **build + unit-test + static designer**
в feedback loop (C6 частично, C7, C8 для серверных тестов).

## Заявления и подтверждения

- **c09-eight-tools** SOURCE. В `McpServer.kt` ровно восемь `@Tool`:
  `run_all_tests`, `run_module_tests`, `build_project`, `dump_config`,
  `launch_app`, `check_syntax_edt`, `check_syntax_designer_config`,
  `check_syntax_designer_modules`.
- **c09-readme-drift** DOCUMENTATION≠SOURCE. README перечисляет ещё
  `list_modules`, `get_configuration`, `check_platform` — в регистраторе
  этого SHA их нет.
- **c09-compact-default** SOURCE. `run_all_tests` / `run_module_tests`
  принимают `full` и по умолчанию вызывают `toResponse(full = false)`.
  Обрезка стека в `Extensions.kt` не читалась — компактность ответа
  заявлена контрактом параметра, формат DTO не доказан запуском.
- **c09-formats** DOCUMENTATION. DESIGNER и EDT; EDT CLI 2025.1+.
- **c09-yaxunit** DOCUMENTATION+частичный SOURCE. Tools зовут YaXUnit
  через `LauncherService`; наличие фреймворка в ИБ не проверялось.
- **c09-ordinary-check-flags** SOURCE. `check_syntax_designer_config`
  принимает `thickClientOrdinaryApplication` /
  `thickClientServerOrdinaryApplication` — это флаги эмуляции CheckConfig,
  не runtime/UI обычных форм. `launch_app` умеет `THICK_CLIENT`.
- **c09-surface** INFERENCE. 8 всегда видимых tools всё ещё шире одного
  verify-capability; прятать за facade.

## Оценка относительно цели

Единственный вход, который связывает обновление ИБ и точечный тест с
ответом ассистенту. Дополняет r01 `unica.run` (сборка/клиент, без YaXUnit)
и r12 `1c-db-*` (скрипты без MCP-отчёта). GPL-3.0 ограничивает встраивание
в закрытый продукт. Готовность продуктовая по коду регистратора; живой
цикл 1С+YaXUnit не запускался.

Предварительное решение: **основной кандидат verify/build**; снаружи
агенту 1–2 facade-операции, не все 8.

## Резюме для пользователя

Проверено: README (11 имён, устарело) и `McpServer.kt` (8 `@Tool`).
Решение: взять как verify-ядро. Следующая проверка: живой отчёт
`run_module_tests` на одном модуле.

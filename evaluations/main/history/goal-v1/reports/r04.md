## Назначение и возможная роль

Rust workspace 0.2.11: CLI и библиотеки чтения `*.hbk`, экспорт фактов
синтакс-помощника в JSON, SQLite/FTS5-индекс, resolver-крейты без MCP.
Это лучший найденный **docs core** (C4, C11, C12): знания живут в индексе,
ответы детерминированные (`ok`/`not_found`/`ambiguous`). Агенту как
отдельный MCP не обязателен.

## Что изучено

Commit `832a5bff810e368f34d005c471481c2091395455`. README, `Cargo.toml`,
дерево `crates/` (hbk-*, syntax-helper-*, context-resolver-*, CLI).
LICENSE в корне нет (API `license: null`; SPDX не установлен). Есть `tests/`, `spec/`,
`openspec/`. Не читались парсеры HBK построчно.

Важное ограничение манифеста: зависимость
`v8-context-semantic-entities = { path = "../v8-context-semantic-entities" }`
лежит *вне* репозитория. Сборка «как есть» может требовать соседний checkout.

## Заявления и подтверждения

- **c04-cli-index** DOCUMENTATION. Команды `syntax export/index/get/search/
  constructors/related`; индекс отдельно от повторного разбора HBK.
- **c04-resolver-lib** DOCUMENTATION. `context-resolver-core` без HBK/SQLite/CLI.
- **c04-baseline** DOCUMENTATION. Подтверждённый baseline платформы
  `8.5.1.1150`; 8.3 — provisional. Контракты export/provider provisional.
- **c04-external-path** SOURCE. Path-зависимость вне repo в `Cargo.toml`.

Формы приложения к C4 неприменимы: это API платформы, не формы конфигурации.

## Оценка относительно цели

Закрывает C4 как библиотека/CLI лучше, чем тяжёлый Elasticsearch (r18) и
конкурирует с r10 (готовый MCP) и `unica.docs`. Для минимальной поверхности
лучше спрятать за одним docs-capability, чем давать агенту весь CLI.
Готовность: богатый код и спеки, но provisional + внешняя path-зависимость.
Не проверяли извлечение на 8.3.27 пользователя.

Предварительное решение: **использовать как core/библиотеку или источник
индекса** для capability docs; не как отдельный широкий MCP. Fallback —
r10, если нужен готовый агентский адаптер без сборки Rust.

## Резюме для пользователя

Полезен для: локальный индекс синтакс-помощника, точечные JSON-факты.
Что не решает: explore/edit/run, обычные формы, готовый MCP. Проверено:
README, состав crates, внешняя path-зависимость. Решение: docs-ядро.
Следующая проверка: собирается ли workspace без соседнего репозитория и
работает ли индекс на HBK 8.3.27.

## Назначение и возможная роль

Python MCP-сервер (пакет 1.37.0, MIT) для токен-эффективного анализа
кодовых баз 1С. Адаптация [rlm-tools](https://github.com/stefanoshea/rlm-tools)
под CF/EDT, метаданные и кириллический BSL. Аудитория — агент, который
исследует большую выгрузку, не загружая файлы в контекст: код выполняется
в песочнице, наружу уходит только `print()`.

Это главный кандидат на **capability explore / navigation** (C1, C2, C9,
C10, C11): 6 внешних MCP-tools и десятки внутренних хелперов. Это не
редактор, не сборщик и не справка платформы. Есть отдельный CLI
`rlm-bsl-index` — признак, что индекс можно использовать без MCP (C12).

## Заявления и подтверждения

- **c02-six-tools** SOURCE. В `server.py` шесть `@mcp.tool()`:
  `rlm_start`, `rlm_execute`, `rlm_end`, `rlm_help`, `rlm_projects`,
  `rlm_index` (строки 1709–2375). README говорит «шесть»; таблица в
  ARCHITECTURE.md озаглавлена «Пять инструментов» и пропускает
  `rlm_help` — расхождение документации, код важнее.
- **c02-sandbox** SOURCE. `rlm_execute` гоняет Python в песочнице;
  в контекст агента предназначен stdout. Process-изоляция, TTL сессий,
  лимиты памяти описаны в ARCHITECTURE.md и подтверждаются наличием
  `sandbox_process.py` / `_service_win.py`. Поведение не запускалось.
- **c02-helpers** DOCUMENTATION + частичный SOURCE. README/ARCHITECTURE:
  53 BSL-хелпера + 8 I/O + 2 LLM. Среди названных: `find_module`,
  `extract_procedures`, `read_procedure`, `find_callers_context`,
  `find_references_to_object`, `find_code_usages`, `get_object_profile`,
  `parse_form`/`parse_form_xml`, `git_search`, `find_defined_types`.
  Реализации хелперов в `bsl_helpers.py` в этом проходе не трассировались
  построчно; XML-парсеры подписок, форм, HTTP-сервисов в
  `bsl_xml_parsers.py` существуют.
- **c02-formats** SOURCE. `format_detector.py`: только `cf` и `edt`;
  иначе `foreign_with_bsl` / generic. Категории включают регистры,
  `CommonForms`, модуль `OrdinaryApplicationModule.bsl`. Это модуль
  обычного приложения, не доказательство разбора обычных форм.
- **c02-forms-managed-xml** SOURCE. `_parse_form_cf` читает
  `Ext/Form.xml` с `ChildItems`, `InputField`, `Events` — схема
  управляемой формы. `_parse_form_edt` читает EDT `Form.form`.
  `FormType`/`Ordinary`/`Form.bin` в этом файле не встречаются.
- **c02-index-outside-context** SOURCE. SQLite-индекс и файловый кэш
  (`~/.cache/rlm-tools-bsl/…`, CLI `rlm-bsl-index`); тела файлов
  остаются на сервере. Progressive disclosure: slim-стратегия +
  `rlm_help` vs `RLM_STRATEGY_MODE=full`.
- **c02-no-edit** INFERENCE. В публичных tools и описании хелперов нет
  операций записи исходников; продукт позиционируется как анализ.
  Ограничение вывода: не читали каждый хелпер на наличие write.
- **c02-author-bench** DOCUMENTATION. Сравнение с RAG на ДО КОРП 3.0
  живёт в отдельном репозитории; для этого аудита это авторский
  benchmark, не собственное измерение.
- **c02-tests** SOURCE. `tests/` + pytest в `pyproject.toml`,
  `fail_under = 70` для coverage. Запуск: NOT_RUN.

## Реализация, зависимости и проверки

Путь: `rlm_projects` регистрирует каталог → опционально `rlm_index build`
→ `rlm_start` определяет формат и поднимает сессию → агент пишет скрипт
из хелперов в `rlm_execute` → `rlm_help` догружает рецепты → `rlm_end`.
Ошибки: таймаут 45 с, hard-kill worker, truncated stdout, foreign-format
gate.

Зависимости runtime: Python 3.10+, `mcp[cli]>=1.26,<2`, опционально
OpenAI/Anthropic для `llm_query`, Git для `git_search`, pywin32 для
службы Windows. Платформа 1С не нужна. Точка входа MCP — HTTP
`127.0.0.1:9000/mcp` или stdio; ядро хелперов и индекса отделено от
транспорта (C12).

Риск для C10: агент *может* увидеть только 6 tools, но качество зависит
от того, будет ли он писать скрипты по хелперам вместо того, чтобы
просить полные файлы. Slim+`rlm_help` этому помогает; `full` снова
заливает ~20К символов справки в старт.

## Оценка относительно цели

- Полезность: лучший найденный на этом шаге ответ на C1, C2, C9, C11
  для больших CF/EDT-выгрузок. C3 частично: модули форм и метаданные
  находятся; структура/обработчики из XML — у управляемых форм.
  Не закрывает C4, C5, C6, C7, C8.
- Готовность: зрелый пакет на PyPI, служба Windows, Docker, тесты,
  явная философия экономии контекста. Для цели — брать как explore-ядро,
  не как исходный «ещё один длинный список tools».
- Доказанность: поверхность и форматные гейты подтверждены кодом.
  Качество callers/подписок/ссылок на регистрах — DOCUMENTATION до
  deep-static `bsl_helpers.py`/`bsl_index.py`.

Альтернативы explore: r15 (универсальный code-index + BSL tools),
r01 (`unica.search`/`view`, слабее по графу), r19 (RAG). Дополняет
r01/r12 (edit) и r09 (build/test). Контрпример: если обычные формы
хранятся как `Form.bin` и агенту нужна их структура — r02 этого не
даст; нужен другой разборчик или runtime.

Предварительное решение: **основной explore/core**; MCP-интерфейс
оставлять как есть (он уже facade), не подключать 60 хелперов как
отдельные tools.

## Резюме для пользователя

Полезен для: исследование больших конфигураций CF/EDT, навигация по
модулям, callers, ссылки на объекты, подписки (заявлено), компактный
stdout, индекс вне контекста. Что не решает: правка исходников,
справка платформы, сборка/запуск, UI-тесты, разбор обычных форм как
структуры. Проверено: 6 tools в коде, детектор CF/EDT, парсеры
управляемых форм, MIT, CLI индекса. Предварительное решение: взять
почти без изменений как слой explore. Следующая проверка: deep-static
хелперов графа и `parse_form` на `FormType=Ordinary` / отсутствии
`Form.xml`.

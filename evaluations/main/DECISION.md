# Выбранный контур агента для разработки 1С

Дата: 2026-09-20. Статус: **решение зафиксировано**, можно внедрять.

Это не рейтинг всех 19 кандидатов и не обещание, что всё уже прогнали
на вашей базе. Это договорённость, **какие продукты входят в контур**.

Исходный обзор 19 репозиториев: [REPORT.md](REPORT.md), карточки в
[reports/](reports/). Vanessa и Answer42 в тот список не входили;
их роль здесь принята по вашей постановке и публичным описаниям,
без отдельного аудита в этом каталоге.

## Что берём

Пять готовых продуктов плюс **тонкая своя обвязка**. Сами движки 1С
(парсер, индекс, справка, сборка, UI-тесты) не пишем.

| Слой | Продукт | Зачем |
|---|---|---|
| Поиск по конфигурации | [code-index-mcp](https://github.com/Regsorm/code-index-mcp) (`r15`, сборка `bsl-indexer`) | Найти объект, модуль, callers, обработчики, не загружая выгрузку в чат |
| Правки, справка, проверка узла, запуск 1С | [Unica](https://github.com/IngvarConsulting/unica) (`r01`) | Читать/менять XML метаданных и управляемых форм, `unica.docs`, `unica.check`, `unica.run` |
| Сборка и серверные тесты | [mcp-onec-test-runner](https://github.com/alkoleft/mcp-onec-test-runner) (`r09`) | Designer/IBCMD, YaXUnit, синтаксис конфигуратора/EDT |
| Живая форма в цикле разработки | [Answer42](https://gitlab.com/platform42/answer42-mcp) ([PyPI](https://pypi.org/project/answer42/)) | Открыть форму, нажать, заполнить, скрин/evidence через Test Client |
| Сценарий и регрессия | [Vanessa Automation](https://github.com/Pr-Mex/vanessa-automation) ([MCP](https://pr-mex.github.io/vanessa-automation/dev/AI/)) | `.feature`, цепочки документов, полноценный UI-сценарий |

Обвязка — не шестой 1С-движок. Это маршрутизатор: агент видит **мало
стабильных операций**, а внутри вызывается нужный продукт. Большие
выдачи пишутся в файлы, в чат — короткий итог.

## Как это выглядит для агента

Наружу (имена можно сменить, смысл такой):

```
агент
 └ обвязка
      ├ explore         → code-index-mcp / bsl-indexer
      ├ docs            → Unica (unica.docs)
      ├ edit            → Unica (unica.view / unica.apply)
      ├ static          → Unica (unica.check) и/или синтаксис r09
      └ verify
           ├ unit       → r09 + YaXUnit
           ├ form       → Answer42
           └ scenario   → Vanessa
```

Правило разведения проверок:

1. Изменился общий модуль / серверная логика → YaXUnit через r09.
2. «Форма открылась, кнопка нажалась, поле заполнилось» → Answer42.
3. Цепочка документов или регрессия → Vanessa.

Не подключать агенту сырой `tools/list` всех пяти MCP сразу: у Unica
11 tools, у индексатора порядка 30, у r09 — 8, у Vanessa и Answer42
ещё пачки кликов и шагов. Без обвязки снова получится «сотни tools».

Unica **не** основной поиск по большой конфигурации (call graph на
поверхности v0.13 нет). Answer42 **не** основной индекс исходников
(у него есть свой RAG по метаданным для подсказок UI — это не замена
`bsl-indexer`).

Эти репозитории **не подключаем**. Не «через день» и не по очереди: их нет в выбранном наборе.

| Было в обзоре | Почему не в контуре |
|---|---|
| [rlm-tools-bsl](https://github.com/Dach-Coin/rlm-tools-bsl) (`r02`) | Тот же слой, что r15. Не включать оба |
| [cursor-1c-skills](https://github.com/Desko77/cursor-1c-skills) (`r12`) и [claude-code-skills-1c](https://github.com/Desko77/claude-code-skills-1c) (`r13`) | Дубль правок Unica |
| [mcp-bsl-platform-context](https://github.com/alkoleft/mcp-bsl-platform-context) (`r10`), [1c-syntax-helper-mcp](https://github.com/Antonio1C/1c-syntax-helper-mcp) (`r18`) | Дубль `unica.docs` |
| Остальные из 19 | Дубль, не та роль или спецслучай (EDT, CI, REST в ИБ, RAG) |

Доставать отдельно, только если контур уже упёрся в конкретный пробел: [v8-context-hbk](https://github.com/alkoleft/v8-context-hbk) (`r04`) — если не хватит справки Unica; [ai-edt](https://github.com/Desko77/ai-edt) (`r17`) — если появится работа внутри EDT. До того их тоже не подключаем.

## Что снято с обязательного

По уточнению заказчика:

- **Совместимость именно с Cursor не обязательна.** Unica штатно живёт
  на Codex / Claude; хост выбираете вы.
- **Обычные формы не обязательны.** Контур рассчитан на управляемые
  формы и файловую выгрузку. Структура `Form.bin` не закрывается и
  сейчас не ищется.

## Какие требования закрывает набор

Обозначения C1–C14 — критерии из [BRIEF.md](BRIEF.md). Кратко:

- Закрывают связкой: поиск без дампа в чат (C1), связи BSL — по заявке
  индекса (C2), метаданные и управляемые формы (часть C3), справка
  (C4), правки XML (C5), статика (C6), сборка/запуск (C7), серверный
  тест (часть C8), индексы вне окна (C11).
- Закрывают **только вместе с обвязкой**: мало tools наружу (C10) и
  цикл «нашёл → поправил → проверил» (C13).
- UI-проверка формы и сценария (остаток C8) — **Answer42 и Vanessa**;
  в обзоре 19 репозиториев этого не было.
- Не закрывают: отладчик с точками останова вне EDT; структура обычных
  форм. Это больше не блокер.

Запусков на вашей базе в этом исследовании не было. Качество графа
r15, отчёт YaXUnit, подключение Unica и живой Test Client — проверка
уже на внедрении, не отдельным аудитом «всех 19».

## С чего начать внедрение

Порядок, чтобы рано получить пользу и не смешивать контуры:

1. Обвязка по [FACADE.md](FACADE.md): 5–8 внешних операций, включение
   только в 1С-проектах, несколько именованных баз; внутри — вызовы
   продуктов, большие ответы на диск.
2. Выгрузка конфигурации + **r15** (поиск) + **Unica** (чтение/правка
   управляемой формы, справка). Хост агента — тот, где удобно поднять
   MCP (Codex / Claude / иной).
3. **r09**: собрать ИБ, прогнать один модуль YaXUnit.
4. Живая база + Test Client: сначала **Answer42** на одной форме,
   затем **Vanessa** на одном `.feature`.

Не включать rlm «на всякий случай». Не подключать Vanessa и Answer42
как два равноправных длинных списка tools без правила unit / form /
scenario.

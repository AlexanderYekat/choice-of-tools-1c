## Главное уточнение: CLI-движок сборки, не ещё один MCP рядом с r09

Точка входа — бинарь `v8-runner` (`src/main.rs` → `app::run`).
Команды `build`, `test`, `syntax`, `dump`, `launch`, `init` работают
без MCP. JSON-конверт (`--json-message`: `ok`, `command`, `duration_ms`,
`data`, `warnings`, `steps`, optional `error`) общий для CLI и MCP
`structured_content`. MCP — узкая обёртка: `v8-runner mcp serve stdio|http`,
ровно **8** `#[tool]`.

Следствие для фасада: `verify.unit` / сборка / синтаксис конфигуратора
лучше звать как one-shot CLI, а не светить MCP. Это **удобнее**, чем
r09 (`java -jar` только как MCP).

Имена MCP-tools совпадают с регистратором r09: `run_all_tests`,
`run_module_tests`, `build_project`, `dump_config`, `launch_app`,
`check_syntax_edt`, `check_syntax_designer_config`,
`check_syntax_designer_modules`. Держать оба в контуре — дубль (C14).

## Предпочтительный адаптер r22

```text
verify.unit(target, module?)
  -> v8-runner --json-message --config <target.yaml>
       test [--no-build] yaxunit module <NAME> | yaxunit all
  -> compact envelope: ok, data.report, data.retained_paths, error
  -> сырой лог платформы в workPath/logs; агенту — JSON

static.designer(target, …)
  -> v8-runner --json-message --config <target.yaml>
       syntax designer-modules --server …

build(target)
  -> v8-runner --json-message --config <target.yaml> build

verify.scenario через runner (не вместо r21):
  -> v8-runner --json-message test [--no-build] va --feature … --scenario-filter …
```

MCP `run_all_tests` **не** имеет `--no-build`: docs явно говорят, что
skip-build — CLI-only. Фасаду для уже собранной ИБ нужен CLI.

Большие отчёты: `data.retained_paths` и файлы в `workPath`; в чат —
`ok` + краткий report. `--full` включает успешные кейсы и длинные стеки
(C9: не включать по умолчанию).

## Сравнение с r09

| | r09 METR | r22 v8-runner |
|---|---|---|
| Стек | Kotlin/Spring JAR, JDK 17 | Rust bin 0.5.1 |
| Вход агента | MCP-only | CLI first, MCP optional |
| MCP tools | 8 в коде (README ещё врёт 11) | те же 8 имён, README=код |
| Конфиг | `application.yml` | `v8project.yaml` + local overlay |
| YaXUnit | да | да (`test yaxunit`) |
| Vanessa | нет | да (`test va`, `launch mcp va`) |
| JSON агенту | MCP response | `--json-message` envelope |
| Лицензия | GPL-3.0 | AGPL-3.0 |

r22 **явно умеет Vanessa**, но как runner, не как замена продукта r21.
`tools download vanessa` берёт `vanessa-automation-single.epf`;
`test va` / MCP `run_all_tests` `runner=vanessa` прогоняет профиль
(feature/tags/scenario-filter) через `/Execute`; `launch mcp va` поднимает
уже Vanessa MCP (`load_features`, `run_scenario`, …) и ждёт ready.
Шаги Gherkin, Feature Player и библиотека шагов остаются в EPF Vanessa.
Фасад при выборе r22 может звать `v8-runner test va` вместо сырого
`1cv8 /Execute` из карточки r21 — это замена адаптера, не движка.
r20 (Test Client формы Answer42) r22 не заменяет.

## Оценка относительно цели

- **Полезность:** C7 (сборка/запуск Designer/клиентов), C6 (CheckConfig/
  CheckModules/EDT validate), C8 unit (YaXUnit) и запуск scenario-движка,
  C9 (JSON envelope + retained_paths), C10 (CLI или 8 tools), C12 (бинарь,
  хост не фиксирован), C13 (build → syntax → test). Explore/docs/edit
  не закрывает. Избегает своего движка сборки 1С.
- **Готовность:** продуктовый CLI; живой init/build/syntax на стенде
  `simple` подтверждён. YaXUnit/Vanessa в этом аудите NOT_RUN.
- **Доказанность:** S1–S5 static; **RUN PASS** init+build+syntax на
  стенде `simple`. Не доказаны: YaXUnit, Vanessa `test va`, incremental
  build, dual-IB.

Контрпример, который оставил бы r09: уже внедрённый METR без желания
менять YAML/лицензию, либо AGPL неприемлем для выбранного способа
доставки. Для нового контура с фасадом контрпример слабый: CLI+JSON+тот
же MCP-контракт строго лучше стыкуется.

Самопроверка: «подключить r22 *и* r09» опрокидывается C14. «Выкинуть
Vanessa из контура, потому что r22 её поддерживает» — нет: без EPF/шагов
r21 (или single-сборки) `test va` нечем исполнять. «Фасад всё равно сам
пишет VAParams и зовёт 1cv8» — слабее, если r22 уже выбран как build-слой.

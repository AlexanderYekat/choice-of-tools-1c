## Главное уточнение: это MCP-драйвер, не пакетный CLI формы

Точка входа `answer42` из `pyproject.toml` — `mcp_1c.server:main`.
CLI поднимает MCP-сервер (stdio по умолчанию, опционально StreamableHTTP).
Одноразовой команды вида «проверь эту форму и выйди» в просмотренном
коде нет: живая сессия создаётся MCP-вызовом `start_session(base_url, session_id)`.

Следствие для фасада: `verify.form` — MCP-клиент к узкому subset tools,
а не обёртка над batch CLI (в отличие от r21 Vanessa). Это **терпимо**,
не «мешает»: пакетный вход есть, это stdio/HTTP MCP без GUI продукта.

На старте сессии нужна живая платформа 1С 8.3.27+/8.5+ (`1cv8c`, `ibcmd`;
`ibsrv` желателен). Windows — интерактивная desktop-сессия, не служба.

## Предпочтительный адаптер r20

```text
verify.form(target, steps...)
  -> long-lived stdio MCP: answer42 --disable-rag --tool-profile ui
       env ONEC_MCP_CREDENTIALS_FILE=<facade secrets>
  -> start_session(session_id=<target>, base_url=<target url or title>)
  -> subset: ui_tree / click_button / set_field_value / screenshot
  -> screenshot/recording PDF -> artifacts (в tool result только path)
  -> compact summary агенту; raw tools/list не показывать
```

`--tool-profile ui` уже есть в продукте: фасад не обязан патчить Answer42,
чтобы спрятать RAG и часть табличных/dynamic tools. Ещё уже —
`core`. Дефолт `full` агенту давать нельзя (C10).

Большой `ui_tree` уходит в MCP resource при пороге ~50k токенов
(`delivery=auto|resource`) — это уже в продукте, не в нашем фасаде.

## Две ИБ

Именованные сессии — штатный контракт: `session_id` на `start_session`
и на UI-tools; словарь `_SESSIONS`; общий `ibsrv` только для **одной**
файловой базы с несколькими клиентами (это не обмен).

Фасад обязан всегда передавать `session_id`, иначе используется
`DEFAULT_SESSION` (`default-{pid}`) и две цели смешаются в одном процессе.
Одновременность двух разных `base_url` в одном MCP-процессе кодом
допускается, runtime не проверялся.

## Project detection

Answer42 не узнаёт 1С-проект по `Configuration.xml`. Для `verify.form`
нужен `base_url`. RAG-discovery (`--rag-source-dir`,
`rag_sources_add_from_directory`) сканирует EDT/XML, но в контуре v2
это не слой explore и не обязательный манифест.

- `click_button` / открытие формы документа не вызывались;
- Windows: интерактивный desktop (здесь сессия агента на desktop).

## Главное уточнение: stdio MCP, не one-shot CLI

Точка входа бинаря `unica` (`unica-coder` `[[bin]]`) по умолчанию —
`interfaces::mcp::run_stdio()`. `--help` объявляет stdio MCP
(`initialize`, `tools/list`, `tools/call`). Отдельных подкоманд
`view`/`apply`/`check` нет. `--daemon`, `--workspace-service`,
`--runtime-job-worker` — служебные режимы ядра, не пакетный CLI фасада.

Следствие: `docs` / `edit.view` / `edit.apply` / `static` — MCP-клиент
к узкому subset tools, с `cwd` = корень 1С-проекта. Это **терпимо**,
не «мешает»: пакетный вход есть (stdio, без GUI продукта). Официальные
хосты Codex/Claude — упаковка плагина, не требование бинаря.

На старте MCP живая 1С не нужна. Платформа требуется операциям
`unica.run` (ИБ/клиент). `unica.docs` работает без допущенного
source-set.

Stdio поднимает **пользовательский демон**
(`UNICA_PROVIDER_STATE_DIR` либо `~/.unica/provider-state`) и передаёт
ему `workspace_hint` = `current_dir()`. Квитанции вызова включают
хеш этого hint: два cwd — два scope, не одна «текущая ИБ на машину».
Одновременность двух живых workspace через один демон NOT_RUN.

## Предпочтительный адаптер r01

```text
docs(query, source?)
  -> cwd=<корень 1С-проекта>
  -> MCP stdio: unica
  -> unica.docs {query, optional source}
  -> если envelope Task working: poll unica.task.result (агенту не светить)

edit.view(source, at?)
  -> cwd=<корень source>
  -> unica.view {} | unica.view {at, limit, cursor}

edit.apply(source, at, ops)   # явно, не молча
  -> unica.apply {at, ops, dryRun: true}
  -> после подтверждения: тот же запрос dryRun: false + ifRev из превью

static.check(source, at?)
  -> unica.check {} | unica.check {at}
```

Агенту не показывать сырой `tools/list` (11 имён). `unica.search` не
использовать как explore (это r15). `unica.run` не основной путь
сборки/YaXUnit (это r22); запасной запуск клиента — только если r22
недоступен.

`dryRun` у `apply` по умолчанию **false**; без `ifRev` применение
отклоняется. Фасад обязан всегда начинать с превью.

Большой `view`: уже есть `limit`/`cursor`; в чат — summary, тело при
необходимости в артефакт.

## Две ИБ и два набора исходников

Именованный `source-set` в `v8project.yaml` и префикс адреса
`main:…` / `exchange-b:…` закрывают **две выгрузки в одном корне**.
Один вызов `apply` не пересекает наборы (`ops[].args.at` обязан быть
тем же source-set).

Информационная база одна на yaml (`infobase.connection`; overlay
`v8project.local.yaml`). Второй стороне обмена — второй корень
(второй `v8project.yaml` + свой cwd/процесс MCP), как у r22.
Глобального «выбери эту ИБ навсегда» в аргументах tools нет.

## Project detection

Без yaml Unica всё равно строит карту из закрытого каталога раскладок.
Маркеры: `Configuration.xml`, `Configuration/Configuration.mdo`,
`src/Configuration/Configuration.mdo`. База: `.` / `src` / `src/cf`
(первый выигрывает). Расширения: `src/cfe`, `src/extensions`.
Фасад может опираться на те же маркеры и на `v8project.yaml`, не вводя
свой обязательный манифест. Операции записи yaml в продукте нет
(`workspace.initialize` снят).

Корень workspace: ближайший предок с `v8project.yaml`, иначе cwd.
Родительский `.git` как каталог **не** останавливает поиск (тест);
`.git` как файл worktree — останавливает.
